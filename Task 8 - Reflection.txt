One important design decision I made was to use Amazon Bedrock AgentCore Gateway as the integration layer between the support agent and the transactional services. Instead of embedding order tracking and refund-processing logic directly into the agent, I exposed these capabilities through Gateway targets connected to the existing Lambda functions. This keeps the agent focused on reasoning and customer interaction while allowing backend services to remain independently deployable and reusable.

The biggest challenge I encountered was getting the complete system working after the local implementation had already passed its functional tests. During deployment, the AgentCore runtime initially could not access the Knowledge Base because its execution role lacked the required bedrock:Retrieve permission. After resolving that permission issue, the loyalty calculator still behaved differently in production because the runtime did not have the required Code Interpreter permissions. I added the necessary AgentCore Code Interpreter permissions to the runtime role and then verified that the production agent could correctly redeem points and calculate the final price. This demonstrated the importance of validating permissions and dependencies in the actual deployment environment rather than relying only on local tests.

For a production environment, I would extend the agent with stronger observability, automated evaluation, authentication and authorization, structured logging, monitoring and alerting, and more comprehensive automated tests. I would also add additional transactional safeguards around refunds and other customer-impacting operations. Finally, I would improve the memory strategy to control what information is retained, establish retention policies appropriate for customer data, and continuously evaluate response quality and tool usage as the system scales.
